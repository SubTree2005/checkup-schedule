# AI 短请求模式

手机端先向 `POST /api/patient/agent/jobs` 提交会话，接口返回 202 和请求编号。模型在后台生成回答，小程序每约 1.2 秒通过 `GET /api/patient/agent/jobs/{jobID}` 获取状态。每个 HTTP 请求不需要等待整段模型生成，从而适应云托管单次连接的时限。

本次修改需要同时部署后端和上传新版小程序。先发布后端，保留服务的 `CHATANYWHERE_API_KEY`、`CHATANYWHERE_MODEL=deepseek-v4-flash` 和其他原有环境变量，再从 `apps/miniprogram` 上传并更新体验版。旧 `/chat` 接口保留以兼容尚未更新的客户端，但旧客户端仍采用长请求方式。

后端启动时自动创建 `patient_agent_job` 表。结果以患者为范围存入共享数据库，查询落到其他服务实例也能取回。只保存状态与回答，不持久化本次输入会话或自定义密钥。请求编号有效期为 15 分钟，过期结果由后续提交请求清理；注销账号时级联删除。

同一客户端提交重试使用相同请求 ID，避免重复调用模型。每名患者最多一条有效的生成任务；查询不会重复生成。生成超过 110 秒会标记超时，客户端整体最多等待约 120 秒；短暂网络失败会有限重试。停止按钮会停止查询并取消结果交付，已发往模型服务的计算可能继续到请求结束。

后台生成使用当前进程的后台任务。服务重启或实例中断时不会重放请求或重新消费密钥，尚未完成的记录会在查询时超时并提示重新发送。服务端超时、密钥缺失和上游失败会保留明确错误，连接超时也不再统一显示为“暂时无法连接服务”。

验证：`python -m unittest tests.test_agent_jobs` 与 `node scripts/test_agent_polling.js`。后者覆盖超过 15 秒的模拟生成、提交去重、断网重试、取消、账号切换和整体超时。
