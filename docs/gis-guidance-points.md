# GIS 导诊点与连续导航

管理员上传 GIS 即可设定必经导诊点，无需额外修改科室表，也不由患者临时添加。

在导诊点的 Point Feature 的 `properties` 中设置：

```json
{
  "id": "poi_1f_b1_service",
  "name": "综合服务中心",
  "featureType": "poi",
  "category": "guidance",
  "route_node_id": "n_o_1f_b1_service",
  "guidanceFor": ["poi_1f_b2_radiology"],
  "guidanceOrder": 0
}
```

保留该 Point 的实际坐标与所属楼层。`guidanceFor` 绑定目标科室的 GIS POI ID（建议使用稳定 ID）或本医院的业务 `deptID`；一个导诊点可绑定多个科室。`guidanceOrder` 越小越先到；相同顺序按楼层及 POI ID 排序。显式空数组表示不作为任何科室的必经点。

导诊点必须通过 `route_node_id` 或 `routeNodeId` 接入可走路网。导航依次计算起点、所有必经点、最终科室的每一段，再连接成每层连续蓝线；紫色标记表示途经点。任一必经点关闭、未接通或不存在可达路径时，不跳过它生成假完整路线，也不显示完整预计时间。

楼层胶囊按行走顺序显示，可点击、拖动或在地图上左右滑动切换；只有一层时保留单选胶囊。每次换层拆分为独立图，中间换楼梯的水平路线保留。如途经点使同一楼层被再次访问，会按行走顺序保留两次访问，而不是错误合并。

本院地图已将综合服务中心绑定到放射科。去放射科：起点 → 综合服务中心 → 蓝点确认的放射科开口；离开放射科：该开口 → 楼梯 → 后续科室，不重复去登记处。旧 GIS 只在已知区域、点位和走廊几何匹配时使用兼容补丁；数据库中上传的原始 GIS 保持不变。

更新后端并重新上传/发布本次小程序版本，才能使用楼层滑块。重新导出 GIS 已包含导诊绑定与确认后的开口。

“直角优化版”使用各层图片像素坐标，而非经纬度。旧导出若没有 `verticalConnections`，后端仅对已知楼梯 ID、匹配的像素坐标和坐标系标记补齐连接；显式空数组仍表示禁用连接。新导出器会将跨层连接端点一并写入对应楼层坐标系，避免只能显示终点楼层。像素坐标模式下，旧放射科开口及导诊点补丁也采用相同坐标系。

可使用 `python scripts/export_orthogonal_gis.py --output <输出文件.json>` 导出修复后的直角图，`--source` 可指定输入 GIS。导出时核验跨层连接的两端均存在且坐标一致。
