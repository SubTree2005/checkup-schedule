# V3：面向真实环境的预测—调度闭环

## 总体结构

V6 不用一个“大模型”同时完成反馈、预测和排程，而是拆成五个可独立替换的模块：

1. `wait_prediction.py`：根据实时排队人数、进行中项目剩余时间、科室容量和历史服务耗时预测等待时间；
2. `feedback.py`：按科室聚合实际等待，抑制个体异常后更新全局等待预测器；
3. `activity_prediction.py`：按患者学习个人移动时间系数，并接收手机传感器适配结果；
4. `rolling.py`：决定何时重排、优化多远的未来以及哪些近期项目冻结；
5. `hybrid.py`：先用启发式算法得到保底可行解，再用 CP-SAT 改善近端拥堵区间。

反馈模块不调用调度器；两个预测模块分别返回 `WaitPrediction` 和 `PersonalActivityPrediction`，不接触路线求解。未来换成 XGBoost、LightGBM、时序模型或独立预测服务时，调度代码无需改动。

## 全局等待与个人活动

- 等待时间属于科室排队系统的全局状态，同一科室的可靠反馈按科室形成稳健微批；
- 活动时间表示患者在院内从一个位置移动到另一个位置的实际耗时，按患者形成独立画像；
- 检查本身的设备占用时间来自 HIS/设备事件，不与个人移动反馈混用；
- 手机加速度只负责提供运动证据，起终点仍由调度状态、扫码、蓝牙或人工确认。

个人活动与传感器字段详见 `personal_activity_v6.md`。

## 等待时间预测

V4 的 `AdaptiveQueuePredictor` 作为没有真实数据时的在线基线：

- 按每台设备的下一空闲时刻模拟 FCFS 队列，避免“总工作量÷容量”在设备剩余时间不均衡时失真；
- 用近期耗时、科室在线 EWMA 和工作日/周末分时段统计估计服务时长；
- 用确定性蒙特卡洛仿真和实际等待残差校准输出 p90，调度默认使用 p90；
- 预测过期或缺失时保留科室原始估计，调度不会因此停止。

具体字段、公式和回放验收规则见 `wait_prediction_v4.md`。

## Rolling Horizon

调度器每次仍生成当天剩余计划，但只把未来 `optimization_horizon_minutes`（默认 120 分钟）交给 CP-SAT 深化优化：

- 默认每 5 分钟重算一次；
- 排队突增、设备停机、患者迟到或临时离开时可强制触发；
- 未来 15 分钟内仍满足硬约束的项目被冻结；
- 进行中项目、患者时间窗、科室服务时间和设备容量始终是硬约束；
- 远期安排保留启发式结果，下一次滚动时再进入精细优化范围。

## CP-SAT 与启发式分工

启发式算法负责：

- 为所有患者快速生成完整的可行日计划；
- 选择患者内部的检查路线；
- 在 CP-SAT 缺失、超时或失败时提供安全降级。

CP-SAT 负责近端邻域：

- 用整数分钟、区间变量和 `NoOverlap` 表示科室资源；
- 在不改变启发式路线顺序的情况下优化开始时间和设备分配；
- 同时降低患者完成时间与相对原计划的改动；
- 默认最多优化 120 个近端项目，默认求解 2 秒；只有质量优于启发式结果时才采用。

这比直接把数千个检查全部交给 CP-SAT 更稳定，也比单纯贪心更能处理局部拥堵。

## 真实上线仍需补齐

- 从叫号、设备或人工操作中获取真实的开始/结束事件；
- 在取得授权的前提下接入手机运动数据，并设置原始传感器数据的短期保留策略；
- 建立预测特征表、模型版本和误差监控；
- 将计划、计划版本、冻结原因和调度日志保存到数据库；
- 对预测异常、求解超时、无可行解和设备停机设置告警；
- 用历史日数据进行离线回放，比较平均完检时间、超时率、步行距离、改序次数和公平性。
