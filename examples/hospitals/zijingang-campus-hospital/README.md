# 紫金港校医院示例整合包

[`workspace.json`](workspace.json) 是可直接用于医院 Web 管理端“一键导入”的数据整合包，包含：

- 当前医院的名称、地址和开放时间；
- 1F、2F、3F 三层基础平面、走廊路网和科室定位点；
- 49 个服务科室或房间、79 个检查/门诊项目；
- 浙江大学校医院官网列出的 7 个体检套餐，均设置为上架状态。

## 使用方法

新建演示医院时，可在医院注册页面直接选择 [`workspace.json`](workspace.json)。系统会原子创建账号、导入完整数据，并按这些套餐和项目固定准备 100 名未激活的演示患者。

已有医院也可以继续使用普通一键导入：

1. 以医院管理员身份登录 Web 管理端。
2. 打开“数据管理 → 一键导入”。
3. 选择 [`workspace.json`](workspace.json)，确认预览数量后点击“一键校验并导入”。
4. 导入成功后，到“套餐管理”和 GIS 页面复核数据；患者小程序会动态显示已上架套餐。

该文件采用 `upsert` 模式，可重复导入。相同业务 `key` 会更新原记录，不会重复创建；任一数据校验失败时整包回滚。完整字段定义见[医院工作区一键导入格式](../../../docs/workspace-import.md)。

## 数据来源

- 1F、2F 科室：现场记录文字；1F 未标门牌的房间按记录保留“具体门牌待核”。
- 3F 科室：现场截图转录；304 办公室属于工作人员房间，未作为患者服务科室导入。
- 套餐、项目和标价：[浙江大学校医院体检套餐](https://zdyy.zju.edu.cn/2017/0724/c37617a1594195/page.htm)。
- 地址和总开放时间：[浙江大学校医院介绍](https://zdyy.zju.edu.cn/37594/list.htm)。
- GIS：仅从已有 `gis/generated` 中读取三层的 `level`、`spaces`、`route_nodes`、`route_edges` GeoJSON 几何；没有采用旧工程中的科室或套餐数据。

## 推断项与使用边界

原始现场记录没有覆盖每个房间的开放时间、并行容量和单项耗时，因此示例按常见门诊流程填写了保守默认值。1F 部分无门牌房间的 GIS 锚点、105 房间位置、消化内镜位置，以及套餐内性别相关项目的适用条件也需要医院上线前现场确认。

官网套餐页面发布时间较早，价格和当前可预约状态可能变化。整合包中的套餐说明已提示以医院当日确认为准，但正式上线前仍应由医院逐项复核；本示例不能替代院方业务资料或现场导诊信息。

## 重新生成

若需从更新后的路网重新构建：

```bash
python build_workspace.py --gis-root <checkup-schedule旧资料目录>/gis/generated
```

生成器只读取上述 GIS 几何文件，并把本目录脚本中整理的现场记录与官网套餐写入 `workspace.json`。生成后建议运行后端集成测试，确保业务引用和 GIS 科室锚点均能被一键导入接口接受。
